# 📊 오프라인 매장(고깃집) 일별 매출 예측 및 외부 요인 분석

실제 매장 1년 치 운영 데이터를 활용한 **일별 매출 예측 및 데이터 누수 검증 프로젝트**

> 이 프로젝트의 결과물은 높은 예측 성능이 아니라, **측정된 성능을 신뢰할 수 있는지 판단하는 검증 체계**다.
> R2 0.508에서 출발해 0.0015까지 내려온 기록이며, 그 하락은 성능 악화가 아니라 **처음의 0.508이 무엇으로 만들어진 숫자였는지 벗겨낸 결과**다.

## 1. 문제 정의

* **배경:** 오프라인 외식업 매장은 날씨·물가·요일에 따라 매출 변동성이 크지만, 대다수 소상공인은 데이터가 아닌 직관에 의존해 식자재 주문과 인력 배치를 결정한다.
* **목적:** 매장 내부 매출 데이터에 기상·거시 경제 지표를 결합해 **일별 매출을 선제적으로 예측**한다.
* **기대효과:** 예측 기반 식자재 재고 관리, 요일·날씨 맞춤형 인력 스케줄링.
* **실제 도달 지점:** 위 기대효과는 현재 데이터 규모에서 달성하지 못했다. 그 판단 근거는 [5. 결론](#5-결론-및-향후-과제) 참고.

## 2. 데이터

| 구분 | 일수 | 기간 |
|---|---|---|
| 원본 수집 | **365일** | 2025-02-01 ~ 2026-01-31 |
| 학습 가능 데이터 | **337일** | 2025-03-01 ~ 2026-01-31 (28일 이동평균 결측 제거 후) |
| ├ dev set | 244일 | 2025-03-01 ~ 2025-10-30 (튜닝·검증 전용) |
| └ 최종 홀드아웃 | 93일 | 2025-10-31 ~ 2026-01-31 (튜닝 과정에서 완전 격리) |

### 모델 입력 피처 (23개)

| 분류 | 개수 | 피처 |
|---|---|---|
| 시계열 (lag / rolling) | 5 | `전일매출`, `전주매출`, `7·14·28일평균매출` |
| 달력 - 요일 더미 | 7 | `요일_월` ~ `요일_일` |
| 달력 - 주기성 | 4 | `월_sin`, `월_cos`, `일_sin`, `일_cos` |
| 도메인 파생 | 2 | `휴일지수`, `연말특수지수` |
| 외부 - 날씨 | 3 | `평균기온`, `강수계속시간`, `비올확률` |
| 외부 - 거시 경제 | 2 | `육류가중평균`, `식료품가중평균` |

* **이동평균 계산에는 `shift(1)`을 적용**해 당일 매출이 자기 자신의 피처에 유입되지 않도록 처리했다.
* **`인건비용`·`식자재비용`·`기타비용`·`테이블수`는 제외했다.** 그날 영업이 끝나야 확정되는 값이라 "내일 아침 예측"에는 쓸 수 없기 때문이다. 자세한 근거는 [VALIDATION.md](./VALIDATION.md) 참고.

## 3. 모델 및 최종 성능

* **알고리즘:** XGBoost Regressor — 개별 외부 변수와 매출 간 선형 상관이 낮아, 비선형 상호작용을 다루는 트리 앙상블을 선택했다.
* **탐색:** `RandomizedSearchCV`(`n_iter=150`, `cv=TimeSeriesSplit(3)`), **dev set 244일 내부에서만** 수행.
* **최종 파라미터:** `max_depth=3`, `n_estimators=30`, `learning_rate=0.03`, `subsample=0.9`, `reg_lambda=1`, `min_child_weight=10`

### 최종 홀드아웃 검증 (튜닝에 전혀 쓰이지 않은 93일, 1회만 평가)

| | **XGBoost** | 이동평균 (7일평균) | Naive (전일매출) |
|---|---|---|---|
| R2 | **0.0015** | -0.0587 | -0.7479 |
| MAE | **693,631원** | 736,859원 | 910,113원 |
| 평균 일매출 대비 오차 | **14.7%** | 15.6% | 19.3% |

R2는 사실상 0으로 통계적 설명력은 없다. 다만 **R2·MAE 두 지표 모두 단순 규칙 베이스라인을 상회**했다.

> ⚠️ 이 93일에는 12월이 통째로 포함되어 있고, 학습에 쓴 dev set에는 12월이 단 하루도 없다. 즉 **모델이 한 번도 보지 못한 계절 구간에서 측정한, 가장 불리한 조건의 점수**다.
>
> ⚠️ 튜닝 과정에서 참고했던 dev set 점수(홀드아웃 R2 -0.063, Walk-Forward 평균 -0.010)는 낙관 편향이 있어 **최종 성능으로 인용하지 않는다.**

## 4. 걷어낸 데이터 누수 5종

이 프로젝트에서 순차적으로 발견하고 제거한 문제다. **각 항목의 실측 수치와 발견 과정은 [VALIDATION.md](./VALIDATION.md)에 전부 기록되어 있다.**

| # | 문제 | 유형 | 조치 | 결과 |
|---|---|---|---|---|
| 1 | 이동평균 계산에 당일 매출 포함 | 시간축 누수 | `shift(1)` 적용 | R2 0.508 → 0.313 |
| 2 | `shuffle=True`로 인접 날짜가 학습셋에 유입 | 시간축 누수 | `shuffle=False` + `TimeSeriesSplit` | R2 0.313 → 0.012 |
| 3 | 예측 시점에 알 수 없는 운영 데이터 사용 | 운영 가능성 위반 | 피처 4개 제거 | **"베이스라인을 이긴다"는 기존 결론이 뒤집힘** |
| 4 | 표본 크기에 비해 과한 하이퍼파라미터 그리드 | 과적합 | 얕은 트리 중심으로 재설계 | Train R2 0.979 → 0.222 |
| 5 | 검증 점수를 보고 하이퍼파라미터를 선택 | 모델 선택 누수 | 최종 홀드아웃 93일 격리 | 편향 없는 대표 성능 확보 |

**3번이 이 프로젝트의 전환점이다.** `테이블수`(≈ 그날 손님 수, feature importance 1위 28%)를 제거하자 Walk-Forward 평균 R2가 0.019 → -0.351로 떨어지고 5개 폴드 전부 이동평균 베이스라인에 졌다. 그동안의 "베이스라인을 이긴다"는 결론이 **예측 시점에 알 수 없는 값이 만든 착시**였음이 드러난 지점이다. 결과를 되돌리는 대신 원인을 추적해 4·5번으로 이어갔다.

## 5. 결론 및 향후 과제

### 현재 모델로 할 수 있는 것 / 없는 것

* **할 수 없음** — 특정 날짜의 매출 금액을 신뢰할 만한 수준으로 예측하는 것 (R2 ≈ 0)
* **제한적으로 가능** — 평균 대비 14.7% 오차 범위의 개략적 수요 가늠. 베이스라인 대비 개선폭은 있으나 실제 발주·인력 의사결정을 맡기기엔 부족하다.
* **확인된 사실** — 거시 변수(CPI)는 일별 예측에 기여하지 못한다. 월 단위와 일 단위의 해상도 불일치, 그리고 트리 모델의 외삽 불가 특성 때문이다. (A/B 검증 결과는 VALIDATION.md 10번)

1번의 기대효과는 현재 데이터 규모에서 **달성되지 않았다.** 성능 수치를 조정해 달성한 것처럼 보이게 하지 않고, 왜 달성되지 않았는지를 근거와 함께 남기는 쪽을 택했다.

### 향후 과제

1. **다년치 데이터 확보** — 연 1회 발생하는 시즌(연말·명절)이 학습셋에 반복 등장해야 `연말특수지수` 같은 피처가 비로소 기능한다.
2. **일 단위 외부 변수로 교체** — 월 단위 CPI 대신 인근 행사 일정, 유동인구 등 일별 해상도 변수.
3. **선행지표 확보 시 재설계** — 예약 건수처럼 예측 시점에 이미 알 수 있는 데이터로 제외한 운영 데이터의 공백을 메운다.
4. **검증 구조 고도화** — 데이터가 늘어나면 Nested CV가 현실적 선택지가 되므로, 현재의 "최종 홀드아웃 1회 평가" 방식에서 전환한다.
